# 食愈屏幕：手机无线传图 MVP

## 验收目标

- 手机连接屏幕发出的 Wi-Fi。
- 手机浏览器选择任意照片，自动裁成 1024 × 600 后发送。
- 屏幕全屏显示照片。
- 断电重启后仍显示最后一次成功上传的照片。

## Arduino IDE 设置

- 开发板：`ESP32S3 Dev Module`
- Arduino ESP32：`3.2.1`（当前真机验证基线）
- Flash Size：`16MB (128Mb)`
- Partition Scheme：`16M Flash (3MB APP/9.9MB FATFS)`
- PSRAM：`OPI PSRAM`
- Upload Mode：`UART0 / Hardware CDC`（使用板上标注 `UART1` 的下载口时沿用此前成功的上传设置）
- 额外库：`TJpg_Decoder` 1.1.0

分区方案必须选 FATFS 这一项，否则图片无法断电保存。

## 使用

1. 编译并上传 `wireless_photo_display.ino`。
2. 正常展示时 Wi-Fi 保持关闭；当前阶段通过右上角设置齿轮验证触摸入口。
3. 看到连接说明后，屏幕背光会关闭。手机连接 Wi-Fi：`ShiYu-Screen-A02`。
4. 密码：`shiyu2026`，浏览器打开 `http://192.168.4.1`。
5. 选择照片，确认预览后点“发送到屏幕”。
6. 在网页“屏幕相册”中可以选择待显示照片或删除历史照片。
7. 点击“完成并返回屏幕”；若无操作，两分钟后也会自动退出传图模式。
8. 正常展示时，在屏幕上左右滑动或点击两侧切换照片。

手机可能提示“此网络无法连接互联网”，这是正常现象，请选择继续使用该网络。

## 当前边界

- 图片采用“裁满屏幕”，不会拉伸变形，但边缘可能被裁掉。
- 当前为本地直连 MVP，不需要路由器和云服务。
- 最多保留最近 20 张，且图片总量不超过 7MB；达到任一限制时自动删除最旧照片。
- 修改分区方案并烧录可能清空此前保存的图片，但不会影响已经备份的原厂固件。

## 已完成、待真机验收的优化

- 现象：传输图片过程中，屏幕会出现短暂抖动或旧画面异常刷新。
- 实现：上传开始后立即插入黑色遮罩，并在屏幕上显示真实传输进度；上传和校验完成后，再一次性切换到新图片。
- 验收标准：传输期间不暴露半帧图片、旧画面或抖动画面；失败时显示失败提示并保留上一张有效图片。
