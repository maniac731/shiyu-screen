# 食愈屏幕技术路线

## 1. 指导思想

**流畅且可持续扩展。** 编译和烧录成功不等于完成；真机响应、代码边界和后续扩展成本共同决定方案是否合格。

## 2. 已确定的产品状态

### 环境模式

- 60 秒无触摸后自动进入，不设置主动入口。
- 以家庭照片为主，动态插入餐食建议、临期提醒和库存摘要。
- 技术上使用数据驱动的 `Photo / Meal / Expiry / Inventory` Slide，不把提醒生成 JPEG。
- 点击照片进入主页；点击信息卡直接进入对应详情；不设计长按。

### 主动模式

- 用户查看主页、库存、吃什么和详情时显示明确导航。
- 右上角设置齿轮只出现在主页；轮播、库存、餐食和详情页不显示设置入口，需先返回主页。
- 导航不在环境模式常驻，避免占用 7 英寸内容空间、破坏照片构图和形成固定高亮区域。
- Back 返回稳定上一级；无操作后回到环境模式。

### 夜间息屏

- 设置中提供自动息屏、早晨恢复时间和环境模式等待时间。
- 第一版只关闭背光，不做 Deep Sleep；夜间触摸只负责唤醒。
- 设备时间不可靠时不执行定时息屏；时间由手机管理或联网校准。

## 3. 关键决策及理由

| 决策 | 理由 |
|---|---|
| 使用 LVGL，不继续扩展手写 `Paint_*` 页面 | 当前逐像素同步绘制导致 3–4 秒切页和触摸阻塞；成熟 GUI 更适合中文、列表、图片、样式和事件 |
| 保留双 framebuffer + VSYNC | 已在真机验证切页完整、无黑屏和残行；两块约占 2.34 MiB PSRAM，不增加第三块全屏画布 |
| 首选厂商 LVGL 9.5 示例作为移植基线 | 厂商已提供 Direct Mode、双 framebuffer、触摸回调和独立 LVGL 任务；先真机验证再扩展 |
| UI、业务、网络和存储分层 | Wi-Fi、Flash 和 JPEG 操作不能阻塞触摸，也不能跨任务直接调用 LVGL |
| 环境轮播与主动导航并存 | 轮播适合长期展示；明确导航满足有目的的查询，两者不必互相牺牲 |
| 设置入口只放在主页 | 保持轮播沉浸、减少固定元素和重复入口，同时让设置位置稳定可预期 |
| 信息卡动态渲染，照片保存在 FFat | 数据可实时变化，避免重复写 Flash；照片仍以压缩 JPEG 节省空间 |

## 4. 目标代码结构

```text
firmware/shiyu_lvgl/
├── platform/
│   ├── display_port.*       # RGB LCD、双 framebuffer、VSYNC、背光
│   ├── touch_port.*         # GT911 → LVGL 输入
│   └── lvgl_port.*          # tick、task、lock、flush
├── domain/
│   ├── app_state.*          # 当前模式、页面、选择项
│   ├── inventory_model.*
│   └── slide_model.*        # Photo/Meal/Expiry/Inventory
├── services/
│   ├── carousel_service.*   # 轮播顺序和权重
│   ├── photo_service.*      # FFat、JPEG、相册
│   ├── clock_service.*      # 时间同步和夜间计划
│   └── phone_portal.*       # Wi-Fi 手机管理
├── ui/
│   ├── ui_controller.*      # 状态切换和导航
│   ├── theme.*              # 颜色、字号、间距
│   ├── components/
│   └── screens/             # ambient/home/inventory/meal/settings
└── shiyu_lvgl.ino
```

规则：只有 UI 任务调用 LVGL；其他任务通过事件队列提交 `PhotoReceived`、`InventoryChanged`、`ClockSynced` 等消息。

## 5. 状态机

```text
ACTIVE
  ├─ 60 秒无操作 → AMBIENT
  └─ 到达夜间时间 → NIGHT_OFF

AMBIENT
  ├─ 点击照片 → ACTIVE/HOME
  ├─ 点击信息卡 → ACTIVE/对应详情
  └─ 到达夜间时间 → NIGHT_OFF

NIGHT_OFF
  ├─ 轻触 → 临时唤醒
  └─ 到达早晨时间 → AMBIENT
```

手机管理、上传、设置编辑过程中暂停自动状态切换。

## 6. 分阶段实现

1. **LVGL 门禁（已通过，2026-11-11）**：独立 `shiyu_lvgl` sketch 已运行主页和触摸按钮，复用 18MHz、20 行 bounce buffer、双 framebuffer 与 Direct Mode；真机反馈即时、显示正常，无数秒触摸阻塞。
2. **状态原型（显示稳定性门禁未通过）**：已实现待机展示、主页、设置三页；状态和触摸逻辑通过，但深色页面仍有明显抖动。由于用户照片内容不可控，不接受以浅色界面掩盖缺陷；深色页面和深色照片稳定前不进入智能轮播。
3. **智能轮播**：加入一种临期卡，验证照片与动态 LVGL 卡片交替显示和点击深链。
4. **主动页面**：增加库存、餐食和按需导航。
5. **服务解耦**：接回 Wi-Fi 上传、FFat、时间同步和夜间息屏。
6. **中文与视觉系统**：生成精简中文字体集，统一组件和主题后再扩充内容。

## 7. 真机验收门槛

- 点击后 100ms 内有反馈，普通页面切换不超过 500ms。
- 绘制期间触摸持续可读取，不出现数秒无响应。
- 无黑屏、残行、明显撕裂或持续加剧的抖动。
- 网络和 Flash 操作不直接阻塞 UI 任务。
- 仍只使用两块驱动 framebuffer；记录 Flash、SRAM、PSRAM 峰值。
- 环境、主动、夜间三种状态及返回路径均可重复验证。

第一阶段记录：LVGL 9.5.0；Flash 23%；内部动态内存 26%；烧录哈希校验通过；用户真机确认触摸与视觉效果良好。

第二阶段记录：三状态与全部返回路径真机通过，但整体门禁未通过。深色渐变、大面积深色纯色待机页均能看见抖动；改成与主页相同的浅色背景后基本不可见。因此抖动与 Wi-Fi、图片解码、透明效果和状态切换无直接关系，更可能是 RGB 扫屏链路的波动在深色大色块上被放大。产品不能限制用户照片颜色，必须修复底层显示稳定性，而不是把浅色主题当作解决方案。

## 8. 暂不实施

- 不做长按、多指和复杂动画。
- 不做 Deep Sleep、语音硬件和云端同步。
- 不继续美化当前手写绘图原型；它只保留为硬件与性能对照。
