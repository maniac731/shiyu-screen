# 云照片轮播与间隔设置

## 目标及边界

`shiyu_idf` 在环境模式轮播本地已缓存云照片。默认10秒，设置页允许5–300秒逐秒调整，明确保存，重启保留。仅一张不重复解码；离开环境模式暂停，重新进入从完整间隔开始。

缓存上限为最近20张、合计8MiB压缩JPEG，单张1MiB以内；不预解码整套相册，不改分区。保留30MHz、DOUBLE_PARTIAL双framebuffer、20行bounce、120MHz PSRAM。其他固件路线不修改。

## 2026-11-24 首次真机失败与修复

- 首版 `0x227b10` 已写入并校验，但启动在FAT挂载调用期间触发CPU0 Interrupt WDT反复重启，不能标为通过；已通过esptool `--after no_reset chip_id`停在下载模式，无擦除。
- 回溯为 `tlsf_walk_pool → heap_caps_get_largest_free_block → esp_flash_read → FAT mount → photo_storage_init`。
- 实测反汇编：`photo_storage_init`栈帧 `0xcb0`（3248B），主任务栈配置3584B，新增迁移中的2048B复制数组及约896B目录使后续存储调用余量不足。
- 修复：迁移复制数组及候选目录改PSRAM堆分配，检查失败并释放，保留原缓存；启动函数整理，UUID检查限长。反汇编栈帧降为 `0x140`（320B），主栈配置、显示配置及分区不变。
- 修复编译 `0x227c30`，APP余28%，diff-check通过；已重新写入2260016字节并Hash verified，原分区表校验通过，无整片擦除。
- 修复后真机正常启动：`Restored 0 cached photos; main stack high-water=1812`，UI运行后内部可用18207B、最大块9728B、PSRAM3641888B。此次启动未复现WDT。相册缓存为空，需联网下载，不能声称迁移旧图成功。
- 当前停在 `Waiting for Wi-Fi`；已请用户开启此前可用热点，轮播与设置持久化仍未device-tested/accepted。

### FAT长文件名配置修复

联网后绑定与相册API成功，但文件提交未成功。发现原配置 `FATFS_LFN_NONE=y`，只支持8.3文件名，与UUID加`.jpg`的40字符缓存名冲突，也使旧图迁移失败。改用 `CONFIG_FATFS_LFN_HEAP=y`、`CONFIG_FATFS_MAX_LFN=64`，同步写入defaults，并加编译guard；没有改分区或格式化。提交失败补充JPEG校验、rename errno、NVS阶段日志。

独立只读QA通过；完整重编译 `0x228d60`，已写入2264416字节并Hash verified（原分区表校验通过）。当前验证以此版为准。

### 多图并发资源失败与缓冲复用

LFN版启动恢复1张旧云图，后成功缓存2张，进入环境模式后10秒timer运行；但下载与JPEG绘制重叠时，出现整帧1228800B对齐分配失败、硬件AES分配失败及LVGL锁超时，不能标为稳定通过。IDF S3 AES bounce实际分块1600B，不是16KiB；内部DMA压力与PSRAM整帧峰值需分别处理。

修复：UI固定复用唯一1228800B PSRAM RGB565照片资源，临时压缩输入<=1MiB，直接解码入该资源，LVGL展示常驻内存描述符，不再走每次绘制的文件JPEG整帧分配。环境模式中先同步排空refresh任务，防止SW双drawunit读取时覆盖；输入申请失败保原图，已触碰输出后解码失败隐藏图显示中性提示。软件AES关闭内部DMA临时分配依赖，TLS证书验证和PSRAM配置保留。RGB显示FB数量仍为2。

重新编译 `0x22a6d0`，APP余28%，diff-check通过；待重刷并发验证。此方案切图读取/解码耗时必须实际记录，不能仅凭设计声称低延迟。
