# 厨房与邀请接口契约

## 已确认产品方案

- 日常内容平权：所有成员可查看、新增、修改、删除本厨房的食材和照片；对应业务表和策略尚待实现。
- 成员管理保留最少权限：创建者为管理账号，负责邀请、移除普通成员和设备解绑；设备解绑接口尚未实现。
- 唯一成员管理入口放在手机网页端。屏幕不生成成员邀请码、不提供成员加入审批或成员管理入口。
- 手机创建者分享邀请链接；接收者打开链接、登录，确认厨房名称后主动接受。长凭证作为链接内令牌，不要求手动抄写，不在屏幕显示。下文长代码仅描述底层 RPC 返回值，不代表产品交互。
- 邀请一次有效、24 小时过期。接受前需受限预览厨房名称，不公开成员或业务数据；预览接口及网页流程尚未实现。
- 一个账号最多属于一个厨房；厨房支持多个成员和多块屏幕。首次设备绑定与成员邀请分开设计。
- 创建者转让、厨房删除、账号注销恢复流程仍待设计。

状态：SQL 已实现，数据库执行测试尚未运行，未部署云端。此阶段没有食材、Storage 或设备授权实现。

已确认：每个账号最多属于一个厨房；厨房支持多成员，创建者管理邀请与移除成员。owner 通过 households.owner_id 判断；客户端不能更改成员或角色。

| RPC | 参数 | 返回 | 权限 |
| --- | --- | --- | --- |
| create_household | p_name: 1–80 字名称 | 厨房 UUID | 已登录、未加入厨房 |
| create_invitation | 无 | 64 位十六进制邀请码 | 创建者 |
| redeem_invitation | p_code | 厨房 UUID | 已登录、未加入厨房 |
| remove_member | p_user_id | void | 创建者，只能移除本厨房普通成员 |

邀请码为两次随机 UUID 拼接，数据库仅存 SHA-256；24 小时过期、成功兑换一次后失效。当前是适合复制粘贴的长代码，后续可封装成链接或二维码，未实现短数字码。生成后前端只向创建者展示，不写日志；邀请记录不向浏览器开放读取。无效、过期、已用或账号已有归属统一返回 invitation unavailable。创建厨房与兑换按账号事务锁串行，兑换按邀请码行锁串行，user_id 主键是最终一厨房约束。

客户端只可 SELECT 本厨房及成员；写入仅走受控 RPC。RLS helper 位于非公开 schema，definer 函数固定空 search_path，并检查 auth.uid()。privilege 撤销涵盖 PUBLIC、anon、authenticated，再逐项授权。

当前不提供厨房删除、owner 退出/转让、普通成员主动退出。成员外键使用 RESTRICT，包含 owner 的 Auth 账号不能直接删除；需要先设计完整数据清理/转让流程。管理员删除账号之前必须处理归属，不能静默产生无创建者厨房。移除成员会立即撤销数据库读取，但不会清理其手机既有缓存；客户端后续需清缓存。历史邀请引用也可能阻止删除账号，后续清理流程须一并处理。

## 验证入口

邀请预览已通过迁移 `20261120000200_invitation_preview.sql` 实现：已登录且没有厨房的接收者调用 `preview_invitation(p_code)`，仅返回厨房名称与过期时间，不消费邀请、不授予数据读取权限。用户点击加入后才调用 `redeem_invitation`，并重新检查有效性。预览不保证后续兑换成功（可能在此期间过期或被使用）。SQL 测试增加预览可重复、无成员权限及匿名拒绝检查；尚未执行数据库测试。

手机邀请链接计划采用 URL fragment 传递令牌，避免默认出现在请求路径与 Referer 中；不接入第三方分析、不记录完整邀请 URL，登录跳转需保留待接受邀请并清理地址栏。网页尚未实现，域名及登录方式仍待确定。令牌是访问凭证，应只分享给预期成员。
