# 厨房库存首版

唯一结果：手机管理真实库存，已绑定屏幕只读展示。用户已确认可选到期日期：名称、单位和日期一致时合并；不同日期分批，无日期的记录相互合并。不实现位置。完整网络/断电/耐久矩阵按用户要求延后，不记为通过。

## 规则与接口

- 新增同名、同单位、同日期（含双方未填）时累加；不同日期创建独立批次；单位不同拒绝，不自动换算。编辑修改当前批次数量，编辑撞已有名称、单位与日期的批次时拒绝覆盖（23505）；任何同名其他批次的单位不同仍拒绝（P1002）。数量最多3位小数，0–999999.999；新增必须大于0。数量为0的记录保留，只有明确删除才移除。
- 同名按去两端空格、不区分大小写匹配。名称最多40字符且120 UTF-8字节；单位最多8字符且24字节，均拒绝控制字符。
- 每厨房最多100批，手机提示及服务端限制；不能静默截断。屏幕按同名同单位汇总、每页6种食材，详情只读查看各批。
- `inventory_write(add/update/delete)`由已登录成员调用，服务端确定厨房，锁成员关系及厨房级库存advisory锁；表启用RLS，仅开放本厨房SELECT，客户端不能直接写表。
- add使用用户+request UUID及规范参数指纹幂等，重复请求不重复累加。update/delete提交expected version，冲突保留输入并提示刷新，不静默覆盖别人修改。
- 创建库存表同时将`household_is_empty`改为真实库存存在检查；有库存的厨房不能在接受邀请时被当成空厨房删除；其他原保护不变。
- `device-api`新增`inventory`，只用独立设备凭据，RPC校验设备绑定、密钥、撤销状态，客户端不能指定厨房。按有序内容及厨房计算revision，相同返回unchanged。
- 一次有界完整快照<=64KiB，避免跨页一致性问题；只有库存请求扩展响应上限，照片API保持4KiB。100条长度限制与Edge实际UTF-8长度检查共同约束，不截断。

## 固件与资源

- `inventory_model`模型、候选快照、库存响应及cJSON节点均分配在PSRAM；不将整库数组放入3584B主栈或内部BSS。首版曾复核初始化栈帧64B、UI刷新336B；日期与批次升级的最新构建及资源证据见对应测试记录。
- 快照独立保存在Flash `stock0.bin/stock1.bin`，含schema/generation/设备ID/厨房ID/revision/条目及FNV-1a校验和。先写完整非活动槽、flush/close，再NVS提交active；失败保当前模型，启动校验回退。不宣称FAT写入掉电原子，也不格式化。
- 离线显示相同设备身份的最近快照并标注缓存；设备未绑定/撤销时不继续声称当前库存可用，身份改变不展示旧设备快照。API成功后更新状态，超时保旧数据。
- 同一个网络worker周期同步库存与照片，正常周期含15秒等待和实际请求时间；新照片批量下载、网络延迟可能拉长，不承诺固定15–30秒最大延迟。
- HTTP、Flash写入及解析在LVGL锁外；界面只读取锁内复制的分页记录。动态食材名使用现有公共CJK正文字体。首页真实计数、预览前四种食材；按日期优先展示，未填写日期排后。已过填写日期和临近提示不等同食品安全判断；菜品推荐尚未实现。
- 保留30MHz、双显示FB、单照片RGB565资源、软件AES、FAT长文件名堆缓冲和原分区；不改其他固件路线。

## 到期日期升级（2026-11-24，尚未部署）

- 新迁移 `20261124000200_inventory_expiry.sql` 保留现有数据，旧记录日期为 NULL；上限100按批次计算。无需修改分区或照片。
- `inventory_write` 追加 `p_expires_on text default ''`：旧请求省略该参数时新增无日期、编辑保留日期；显式 null 清空日期；YYYY-MM-DD 设置日期。非法日期拒绝22023。没有重载RPC。无日期新增指纹保持旧算法，已有幂等请求仍可重试；带日期请求指纹包含日期。
- `device_inventory.items[].expires_on` 为ISO日期字符串或null；按日期升序、无日期最后，同日按名称及ID排序。过去日期自然最前。revision包含完整有序内容和日期，因此日期变化会触发快照更新。旧固件会按记录显示各批，日期展示需要新版固件。
- 手机新增和编辑含可选日期，列表逐批展示日期，清空日期输入会明确提交null。
- 用户后续操作：审核并应用该新增迁移，发布网页；Edge转发接口无需改动。然后验证手机新建不同日期两批、同日期累加、清空日期、编辑冲突保留输入，以及屏幕批次和排序。当前未执行远端SQL、部署或烧录。
