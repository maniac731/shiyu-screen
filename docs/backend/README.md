## 数据流与权限

成员方案已确认：日常食材与照片内容平权；创建者管理邀请、移除成员及设备解绑。成员管理唯一入口为手机网页端，采用分享邀请链接、登录后主动接受；屏幕不做成员审批。具体规则与实施状态统一维护在 [厨房与邀请接口契约](household-contract.md)。

手机通过用户会话读取授权家庭的数据；照片文件进入私有 Storage，数据库保存文件元数据。屏幕使用独立且可撤销的设备授权获取家庭快照和受限照片下载地址，不使用数据库管理员密钥。设备绑定与照片同步见 [设备接口](devices.md)。

云端作为共享数据源，屏幕保留本地缓存；断网时展示上一次成功同步内容。首版优先手机编辑、屏幕读取，离线双向编辑不在首版范围。

## 落地顺序与门禁

1. 明确 schema、成员权限及设备授权契约。
2. 编写迁移、RLS 与私有 Storage 策略；用两个家庭测试隔离。
3. 实现手机登录、食材编辑和上传。
4. 实现设备绑定与屏幕同步，再验证断网缓存。

验收必须包含：未登录拒绝、跨家庭读写拒绝、设备撤销生效、上传类型/大小限制、手机修改同步到屏幕。保存脱敏测试证据；本地检查、云端部署和真机接受分别记录。

硬件显示基线以 `../architecture.md` 为准：30MHz + DOUBLE_PARTIAL 双 framebuffer，后端开发不随意调整。
