# 无线传图 MVP 架构

## 用户流程

1. 屏幕启动本地热点 `ShiYu-Screen-A02`。
2. 手机连接热点并访问 `http://192.168.4.1`。
3. 用户从相册选择图片。
4. 手机网页按“裁满”策略生成 1024 × 600 预览。
5. 网页将像素转换成 RGB565，并通过 HTTP 上传。
6. ESP32 写入临时文件，校验固定长度后替换当前有效图片。
7. 屏幕刷新；下次启动从 Flash 恢复图片。

## 当前数据格式

- 分辨率：1024 × 600。
- 像素格式：RGB565，小端序。
- 单张大小：1,228,800 字节，约 1.17 MiB。
- 存储：板载 16MB Flash 中约 9.9MB FATFS 分区。
- 运行内存：板载 8MB PSRAM 承载 LCD 帧缓冲和图片缓冲。

选择未压缩 RGB565 是为了让第一版不依赖额外图片解码库，并优先验证端到端传输。

## 下一版目标架构

- 手机上传经裁剪压缩后的 JPEG，而不是 RGB565 原始数据。
- ESP32 保存图片文件和轻量索引，在显示时解码至 PSRAM 帧缓冲。
- 相册设置固定存储预算，而不是只按张数判断；达到预算时删除最旧图片。
- 上传阶段使用独立遮罩和进度状态，不刷新未完成的图片数据。
- 只有文件完整写入并通过校验后，才更新“当前图片”索引。
