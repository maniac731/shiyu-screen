# 食愈硬件屏幕闭环

只在 AGENTS.md 定义的深度模式触发。读取与任务直接相关的最少文档，不重复加载整个项目背景。

1. 需求不清时才调用产品 Agent。
2. 成熟方案未知时调用方案研究；跨层或资源变化时调用架构。两者可在独立时并行，但最多两个子 Agent。
3. 高风险或疑难故障才让 QA 在开发前定义证伪条件；其他任务只在实施后验证。
4. 证据足以支持本次改动后，由一个开发 Agent实施；随后串行 QA。
5. 只有阶段完成或形成重要决定时才调用秘书；只有用户明确需要理解时才调用老师。

子 Agent返回限于结论、证据、风险、建议和未验证项，不复述完整背景。最终严格区分 implemented、compiled、flashed、device-tested 和 accepted。
